# Channel Video Fetching Analysis

## Current Implementation

The channel video fetching uses the **QuotaEngine** class from `src/lib/youtube/quota-engine.ts` via two main API endpoints:

### 1. GET /api/channels/videos/fetch
Used by the channel videos page (`/channel/[id]/videos`) for viewing videos.

**Flow:**
- Initial load: `QuotaEngine.smartFetchVideos()` with mode='initial'
- Load more: `QuotaEngine.loadMoreVideos()` with pageToken
- Refresh: `QuotaEngine.smartFetchVideos()` with mode='refresh'

### 2. POST /api/channels/sync
Used by the "Sync" button to fetch videos and save them to user's library.

**Flow:**
- Calls `QuotaEngine.smartFetchVideos()` with mode='refresh' or 'loadMore'
- Saves videos to user's Video table

## 3-Tier Fetch Strategy

The QuotaEngine implements:

1. **Cache First** (VideoCache table)
   - Returns cached videos immediately
   - Checks if cache is fresh (< 15 min for initial, 24 hours for refresh)

2. **RSS Fallback** (free)
   - URL: `https://www.youtube.com/feeds/videos.xml?channel_id={channelId}`
   - Returns ~15 most recent videos
   - Used when cache is stale or empty

3. **API Fallback** (1 token/request)
   - Uses `playlistItems.list` with uploads playlist ID
   - Gets all videos with pagination via nextPageToken

## How to Verify

1. **Frontend**: Check the source badge in UI (API/Cache/RSS)
2. **Backend**: Add logging to see which path is taken
3. **Database**: Check ChannelCache and VideoCache tables

## Current Issues/Gaps

1. **isLive column**: Added migration but need to verify it's being used
2. **RSS freshness**: Currently 15 min for initial, 24 hours for refresh
3. **Token consumption**: API calls consume user tokens (1 unit per request)

# Automated Channel Sync via GitHub Actions

## Goal
Create automated background refresh of YouTube video cache using GitHub Actions + Vercel API route.

## Existing Patterns to Follow
- CRON_SECRET pattern exists in `src/app/api/user/cleanup/route.ts:7-16`
- QuotaEngine in `src/lib/youtube/quota-engine.ts` already handles RSS→API fallback

## Implementation Plan

### 1. GitHub Actions Workflow
File: `.github/workflows/daily_sync.yml`

```yaml
name: Daily Channel Sync
on:
  schedule:
    - cron: '0 0 * * *'  # Midnight UTC daily
  workflow_dispatch:
    inputs:
      force:
        description: 'Force sync all channels'
        required: false
        default: 'false'

jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - name: Trigger Vercel sync
        env:
          CRON_SECRET: ${{ secrets.CRON_SECRET }}
          VERCEL_APP_URL: ${{ secrets.VERCEL_APP_URL }}
        run: |
          response=$(curl -s -w "\n%{http_code}" -X POST \
            "$VERCEL_APP_URL/api/cron/sync-channels" \
            -H "Authorization: Bearer $CRON_SECRET" \
            -H "Content-Type: application/json" \
            -d '{"force": ${{ github.event.inputs.force }}')
          
          body=$(echo "$response" | sed '$d')
          code=$(echo "$response" | tail -n1)
          
          echo "$body"
          
          if [ "$code" -eq 200 ]; then
            echo "Sync completed successfully"
          else
            echo "Sync failed with status $code"
            exit 1
          fi
```

**Secrets to add in GitHub:**
- `CRON_SECRET` - Same value as Vercel CRON_SECRET
- `VERCEL_APP_URL` - Your Vercel app URL (e.g., https://your-app.vercel.app)

### 2. API Route
File: `src/app/api/cron/sync-channels/route.ts`

**Security:**
- Validate `Authorization: Bearer CRON_SECRET` header
- Reuse existing CRON_SECRET pattern from cleanup route

**Database Query:**
- Fetch all unique `youtubeId` from `ChannelCache` table (global cache)
- OR fetch all channels that haven't been synced in 24h from `ChannelCache.lastSyncedAt`

**Processing Logic:**
- For each channel youtubeId:
  - Get uploadsPlaylistId from ChannelCache (or convert UC→UU)
  - Call `QuotaEngine.smartFetchVideos()` with mode='refresh'
  - Videos are already UPSERTed to VideoCache by QuotaEngine
  - Update `ChannelCache.lastSyncedAt` timestamp

**Optimization for Vercel timeout (10-60 seconds):**
- Process in small batches (e.g., 5-10 channels per request)
- Use `await Promise.all()` for parallel processing within batch
- Add a simple queue mechanism or track progress
- Return immediate response and continue processing in background using Vercel Background Functions (if on Pro plan) or rely on next cron run

### 3. Error Handling & Logging
- Return JSON with:
  - `syncedCount`: number of channels processed
  - `failedCount`: number of failed channels
  - `errors`: array of error messages
  - `quotaExhausted`: boolean flag
- Log each channel processed with timestamp
